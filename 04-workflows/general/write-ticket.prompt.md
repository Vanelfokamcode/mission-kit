# Tickets

Réponds en français. Deux modes : A (comprendre un ticket reçu) ou B (écrire un ticket). Je précise le mode.

## Mode A : comprendre un ticket
Texte du ticket : [COLLER]
1. Reformule ce qui est demandé en 3 lignes.
2. Ce qui est clair, ce qui est ambigu, ce qui manque.
3. Critères de fin : propose-les s'ils sont absents, à valider avec la personne qui a écrit le ticket.
4. Dépendances, risques, zones du code probablement concernées (à vérifier dans le code).
5. 3 à 5 questions à poser, classées par importance.

## Mode B : écrire un ticket
Ce que je veux obtenir : [DÉCRIRE]
Produis : titre court et précis ; contexte et pourquoi ; comportement actuel et comportement attendu ;
critères d'acceptation vérifiables (chacun testable par oui ou non) ; hors périmètre ; tests à prévoir ;
estimation à confirmer avec l'équipe ; liens et pièces utiles.

## Règles
- N'invente aucune exigence : ce qui n'est pas dit est une question.
- Garde les critères mesurables : "rapide" ou "propre" ne sont pas des critères.
- Pas de donnée sensible dans un ticket : termes génériques.
